# Aven Tasks

## Activation Contract

Use when the user works with `aven`, the local-first task manager: finding,
triaging, updating, scheduling, or handing off tasks, and when a repo routes
work through aven. Prefer aven over markdown task files unless the user points
at a file. Do not create tasks unless the user asks or active agent
instructions enable it. Run `aven doctor` when workspace or project routing is
unclear, and read [references/aven-cli.md](references/aven-cli.md) before the
first mutation in a session.

## Hard Rules

- Run commands from the repo whose tasks you want. Add `--workspace` only to
  target another workspace; let aven infer the project unless told otherwise.
- Never create tasks unless asked or explicitly enabled.
- Task refs identify local tasks. Keep them out of commit messages, PR
  descriptions, and external systems.
- Mark work `active` when starting it and `done` only when complete. Never
  close partial work.
- Inspect dependency and conflict context before changing status or order.
  Resolve conflicts one at a time; never in bulk.
- Keep secrets out of titles, descriptions, labels, projects, metadata, notes,
  and logs.
- Prefer human-readable output. Use `--json` only for scripts.

## Decision Gates

| Situation                  | Action                                          |
| -------------------------- | ----------------------------------------------- |
| new task, untriaged        | omit `--status` (defaults to `inbox`)           |
| task already triaged       | set `--status` on `add` or `edit`               |
| execution order            | `dep add <blocked> <blocker>`                   |
| context only, no order     | `related add <task> <other>`                    |
| group under a theme        | `epic add <child> <epic>`                       |
| defer attention to a date  | `edit --available-at`                           |
| hard deadline              | `edit --due`                                    |
| long text                  | `--description-stdin`/`--file`, `note --stdin`  |
| broad field change         | `bulk-update ... --dry-run` first               |
| unclear workspace/project  | `aven doctor`                                   |
| sync conflict              | `conflict show`, then `conflict resolve --use`  |

## Execution Steps

1. Orient: `aven list --ready`; narrow with `list --open --project/--label`.
2. Inspect before acting: `aven context <ref>` (`show <ref>` for one line).
3. Mutate: `edit`, `note`, `add`, `move`, `dep`/`related`/`epic`, `recur`,
   `attachment`, `text`.
4. Leave handoff: `aven note <ref> --stdin` with decisions, blockers, and
   partial progress.
5. Complete: `edit <ref> --status done`.

## Output Contract

Report the ref printed by aven, the field or status transitions, and any note
text left. Surface unresolved conflicts and blockers.
